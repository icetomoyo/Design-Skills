# Critique / Review 协议（M4）

双层审查：确定性检查（脚本）+ 语义启发（Agent 判断）。结论必须分层标注，不得把主观判断包装成错误。

## 1. 静态层（必做，永远可用）
node scripts/checks.mjs <目标> --contract .vismith/contract.json --json
解读规则：
- severity=error & confidence=certain：确定性错误，直接列出并给修复建议
- error & heuristic（如 CHK-05）：高度可能的问题，标注"需确认"
- warning：契约偏离或一致性风险，按契约优先级评估
- info：说明性输出（豁免、降级提示、跳过原因）

### 豁免分级（v0.2，Floor/Reflex）
- **floor**：`error + certain` 的发现（如契约模式低对比、img 缺 alt、html 缺 lang）——**不可豁免**，尝试豁免会被拒绝并在 detail 留痕。
- **reflex**：其余发现可豁免，但 `.vismith/rules.json` 中的条目须满足：`files`（匹配路径）+ `reason`（去空白/标点后 >=12 有效字符的具体依据）+ 可选 `evidence`（证据引用）；理由不足视为无效豁免，保持原严重度。
- 豁免是设计决策：每次有效豁免自动留痕于 findings；连续豁免同一规则应考虑把它写进 contract 约束而不是继续豁免。

## 2. 语义层（Agent 判断，逐项标注置信度）
按类别 checklist 检查（routing.md 类别列）：
- 视觉层次：首屏焦点是否唯一、扫读路径是否成立
- 信息密度：与类别/意图轴匹配度（admin 过疏、营销页过密都是问题）
- 一致性：同类组件样式/间距/文案语气一致；与 contract 偏离处列出
- 状态完整性：空/载/错/成
- 文案：与 copy-tone 知识对照（无 hype、有具体性）
每条输出：发现 | 证据（文件:行 或 "视觉观察"）| 置信度（高/中/低）| 建议。
低置信度纯审美判断必须写"建议"而非"问题"。

## 3. 视觉层（v0.3，当前占位）
需要浏览器截图与 DOM 关联的能力尚未提供（ADR-4）。当前模式：只出 §1+§2 结论，并明确声明"未做像素级视觉验证"。宿主已具备多模态且用户提供了截图时：按 §2 清单看图，结论同样分层标注。

## 4. 报告
落 .vismith/reviews/<日期>-<范围>.md：静态 JSON 摘要 + 语义发现 + 未验证项声明。修复后再审查时对比上次报告，只报新增与未解决项。
