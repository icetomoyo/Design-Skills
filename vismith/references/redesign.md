# Redesign 协议（授权范围内的重设计）

redesign 与 refine 的区别：允许改变风格方向与布局结构，但仍在契约与授权范围内。

## 1. 授权确认（必做，缺一不可）
- 范围：哪些页面/区块
- 保留项：invariants（功能/行为/视觉红线逐条确认）
- 方向变化幅度：微调（同方向优化）/ 中度（换布局或密度策略）/ 大改（换风格方向）
未明确授权时按 refine 执行并说明。

## 2. 现状固化
contract.md §3 提取契约（若缺）；截图/结构快照留档到 reviews/（无浏览器则记录结构清单）作为回归对照基线。

## 3. 方向变更
- 新方向过五行框架（generate.md §1）；与旧方向的差异点列表给用户确认
- tokens 变更走契约变更纪律：decisions.log 记录每个被替换的 token 及理由

## 4. 迁移策略
- 逐页迁移，每页走 generate 的自检循环 + refine 的 invariants 复核
- 未迁移页面与已迁移页面并存时，在 exceptions.md 标注过渡期与范围

## 5. 回归验证
- 全量 checks --strict
- 对照 §2 基线：功能清单逐项核对（路由、操作、数据展示）
- 有意的变化（视觉）与异常回归（功能丢失）分开报告
