# E5 评测方案（提示贫乏 × 设计自由度，2026-11-22 草案）

**状态：未执行。** 定位：E4 的判别力补强——E4 证明'完备任务书下 skill 边际收益收窄'（S7 四臂打平），E5 反向测验：**提示极简 + 内容新颖 + 无标准版式**时，设计智能必须由代理（或其 skill）自行供给。

## 1. 方法论：把'提示完备度'变量反转
- E4 任务书 1-2KB（结构/组件/mock 全指定）；E5 任务书**一句话**，四臂逐字相同
- 交付限定单文件 HTML（内联 CSS/JS、零网络）——非设计提示，只为可渲染可盲评
- 假设：H1 = 提示贫乏下 A 臂产出'AI 模板脸'率显著上升；H2 = 挂 skill 臂在信息设计/视觉构成维拉开 ≥1 分档

## 2. 场景选择（判别力优先：训练数据稀疏 + 版式无正解 + 视觉承载核心）
- **P1 马尔可夫链**：无公认版式，可视化选择完全开放。提示：**'做一个网页，讲马尔可夫链。'**
- **P2 五度圈**：环形/放射构图是模板模型最弱区。提示：**'做一个网页，讲五度圈。'**
- 备选：信息熵、咖啡萃取化学

### 提示纪律（用户 2026-11-22 纠正后固化）
- 任务提示 ≤10 字量级，**逐字固定、四臂相同**；禁止包含：受众定位、可视化形式、版式结构、组件清单、风格词
- 受众与信息设计由代理自行推断——这本身就是被测能力（'提示完备度 vs skill 能力'的隔离正依赖于此）
- 交付约束（单文件 HTML/零网络）作为**环境规则**随约束块下达，不进任务提示（不构成设计暗示）
- 方法论细节（判别力逻辑/slop 清单/评分维）只存在于评测方文档，生成者不可见

## 3. 臂与规模
复用 E4 四臂定义（A 无 skill / B ui-ux-pro-max d643997 / C impeccable 2b86d9c / D Vismith@HEAD）。**4 臂 × 2 场景 × 2 seed = 16 份**（提示贫乏方差大，n=2 起步；同 E4 规模）。

## 4. 评测升级（相对 E4 的三处强化）
1. **真实渲染盲评**：单文件 HTML 可直接渲染——根侧统一截图（多视口），grader 评'像素级视觉'而非'代码级推断'（E4 局限之一就此清偿）
2. **slop-rate 指标**：定义模板特征清单（居中 hero+三卡/紫渐变/emoji 图标/玻璃拟态滥用等），机器可查项 grep + 人工项盲评，按臂统计命中率
3. rubric 六维改为：信息设计/视觉构成/交互有效性/文案具体性/可达性/反模板（E4 的'契约/状态'维不适用单文件场景）

## 5. 纪律沿用
E4 全套：臂间隔离/禁网络/npm/浏览器（生成期）、脱敏打标、双盲 grader+仲裁、确定性 checks 统一复跑、事故如实记录；B/C 臂硬隔离禁 vismith。D 臂走 vismith 全流程（其 SPOC：路由可能判 generate×education，contract init 仍适用）。
