# Trigger 描述语义筛查结果（2026-11-17）

## 方法与边界（ADR-9 诚实声明）
- 方法：**会话内子代理单判官**。判官只读 vismith/SKILL.md frontmatter 的 name/description，
  对 14 条无标签用户请求逐条判 use/not_use；根级对照 cases.json 期望标签计分。
- 按 skill-creator evaluation.md 纪律，这是 **description semantic screening**：
  不是 SDK 独立执行（未用 run-trigger-eval.js——其需外部 provider 凭据，会话不继承），
  不是真实触发率（无完整 catalog/工具调用证据），单判官无一致性度量。
- 用例：eval/trigger/cases.json（正例 8 / 反例 6，满足 PRD 验收 >=8/>=4）。

## 结果
判官输出与期望标签 **14/14 一致**（precision = 1.00, recall = 1.00，n=14）。

- 正例 8/8 判 use：仪表盘生成 / 对比度修复 / landing 重设计 / 设计规范 / 表单 a11y / WCAG 审查 / 表格精修 / 去 AI 味
- 反例 6/6 判 not_use：后端接口 / React bug 修复 / 行为保持重构 / ER 图 / 框架选型 / 文案翻译

## 判官依据摘录
"面向真实前端代码库内的 UI 设计/生成/精修/重设计/审查与设计体系维护，含对比度等静态检查；排除纯后端与非代码库创作。"

## 局限
- 单判官、单次运行，无 inter-rater 一致性；
- 反例未覆盖"邻近 skill 竞争"场景（catalog 内无竞争 UI skill 时判 use 的边界会更宽松）；
- 结论仅支持"description 与任务意图匹配良好"，不支持"生产触发率"。
