SQLite 的同步层：
本地先写，按列合并

LiteSync 给标准 SQLite 文件加一层 CRDT 复制。应用只面向本地库编程，写入不经过网络；同步在后台传增量变更集，断网不阻塞，恢复后续传。

快速开始 GitHub 仓库

MIT License · 数据格式就是 .db 文件，可用 sqlite3 直接打开

01 · 写路径

先写本地 WAL，再谈同步

应用面向标准 SQLite 文件编程，LiteSync 只在 WAL 之上捕获变更。中继宕机、断网、权限调整，都不阻塞界面写入；恢复后按序回放变更集。

数据格式
标准 .db / WAL 文件，可用 sqlite3 CLI 直接打开与备份
写入口径
本地事务提交即返回，无网络往返
冲突单位
列级 last-writer-wins，整行不会被远端覆盖

02 · 同步协议

同步走增量变更集，不是整库拷贝

首次同步传全量快照与 schema；此后只传 WAL 差分生成的 changeset。传输中断从断点续传，不重发已确认的字节。

首次同步
全量快照 + schema 版本
增量单位
changeset：变更行 + 因果时钟（Lamport）
中断恢复
按 epoch 与字节偏移续传

03 · 边界

中继读不到你的数据

changeset 在客户端加密后才交给中继；同步范围用 SQL 谓词声明，规则随 schema 版本化，可进代码评审。

加密
客户端 AES-GCM，中继仅见密文
权限
行级 SYNC RULES，谓词即 WHERE 子句
可审计
规则与 schema 同仓库演进，diff 可见
