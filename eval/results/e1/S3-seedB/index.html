How LiteSync works

Three claims, each checkable against the source: offline merges are deterministic, your schema survives untouched, and the sync state is plain SQL.

Offline for a week? The writes still merge.

Every change is a row-level delta stamped with a logical clock. When two peers meet, deltas merge by rule — same inputs, same result, on every device. Conflicts resolve deterministically, not in favor of whoever synced last.

It attaches to your database, not around it.

LiteSync loads as a SQLite extension beside your existing file and keeps its bookkeeping in namespaced tables. The schema you designed, the triggers you tuned and the SELECTs you optimized keep running unchanged.

The sync queue is a table you can SELECT.

Pending deltas live in a regular SQLite table with a documented layout. Inspect it, join it against your own data, back it up with the tools you already use — nothing is sealed inside a binary blob.
